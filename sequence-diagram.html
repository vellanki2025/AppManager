Vehicle, Cloud API, and the Versions, Regions and Garage components, including VIN lookup and event history.

1. Update check, with event logging

Versions is the master copy for each VIN. It holds the current snapshot (software version plus app versions) and an append-only event history. Steps 2, 9 and 13 write to it.

Solid arrows are requests, dashed arrows are responses.

What each step carries

  1. Check-in: the vehicle sends its VIN, its software (OTA) version and the version of each installed app.
  2. Save state / stored state: Versions updates the snapshot for the VIN and returns the previous one. If the reported software or app versions differ from what was stored, Versions records an event for each change. This also catches updates made outside the flow, such as a dealer reflash.
  3. Apps needed / app list: Regions returns the allow-list of apps for the VIN's region and model. An app not listed is never offered.
  4. Builds for apps / builds and ranges: Garage returns every available release with the minimum and maximum software version it supports.
  5. Match, pick latest: keep releases compatible with the vehicle's current software version and newer than the installed version, then take the highest. A vehicle on OTA 4.0 never sees media 3.3.
  6. Log offered: an "offered" event records exactly what was sent to this VIN and when.
  7. Manifest, install, report, log result: the vehicle installs from the manifest and reports success or failure. The Cloud API records an "installed" or "install failed" event and updates the snapshot.

2. VIN lookup: current versions and history

For a given VIN, an operator tool (support portal, dealer tool or dashboard) gets the current software version and app versions, plus the full history of software updates and app updates. Both come from Versions through the Cloud API.

Steps 2 to 5 can run in parallel. Regions and Garage are only needed if you also want an "update available" flag in the result.

What the lookup returns

  • The vehicle: VIN, region, software version and the installed version of each app.
  • When the vehicle last checked in.
  • The history for that VIN, newest first: each software update and app update offered, installed or failed, with the time, the version before and after, and where the information came from.

3. What Versions stores

Current snapshot (one record per VIN)

ItemNotes
VINUnique key for the vehicle.
Region and modelUsed to ask Regions which apps apply.
Software versionLast reported OTA version.
App versionsInstalled version of each app, as last reported.
Last seenTime of the last check-in.

Event history (append-only, many per VIN)

ItemNotes
VIN and timeIndexed together so the history for one VIN is a single ordered read.
Event typeSoftware update offered or installed, app update offered or installed, install failed, rollback.
TargetThe software, or the name of the app.
Version before and afterWhat changed.
SourceCloud (an offer), vehicle (a reported result), or detected (found by comparing a check-in with the stored state, such as a dealer reflash).

Events are never edited or deleted. A correction is a new event, so the history stays trustworthy for audits and support cases.
