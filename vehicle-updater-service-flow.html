Sequence diagrams, rules, in-app experience and lifecycle events for the on-vehicle update service in Lucid App Updates. Two cases: the 1 AM automatic update and Update now. Vehicle side only; the Cloud API appears just as the boundary.

What the user sees when an app is updated

The service decides only from vehicle state: a fixed baseline (driving: never download or install; parked: download, then install with a message on the HMI) plus per-app install rules from the manifest, such as "not in egress mode". It does not ask individual apps, or the system, what an app is doing.

Rules for the two cases

One decision table for the 1 AM automatic update and Update now. Numbers are placeholders to confirm with the vehicle and platform teams.

Hold reasons

When a check fails, the update is HELD with one reason and resumes when the checks pass again: driving, install_rule (with the rule name, for example egress_mode), vehicle_active, low_battery, poor_network, outside_window, low_storage. The HMI shows the reason in plain words.

Install rules in the manifest

The Release Manager sets the rules per app. They come in the signed /v1/manifest response, are saved with the update on the vehicle, and are checked at install time. Downloads are never gated by them. Rules can only add limits: the baseline (never while driving, battery minimum) always applies and cannot be loosened.

{
  "appId": "com.lucid.navigation",
  "versionCode": 40100,
  "installRules": {
    "blockedModes": ["egress"],
    "ignition": "any"
  }
}

Lifecycle events sent to Analytics

The service saves each event first, then sends it in a batch. Event names and fields are proposed and should be aligned with the Analytics schema.

Fields on every event

eventId (unique, for de-duplication), appId, releaseId, fromVersionCode, toVersionCode, trigger (auto_night or update_now), profileType (primary or secondary, Update now only), network (wifi, cellular or other), attempt, reason (failures), heldReason (holds), ruleName (install_rule holds), timestamp. The vehicle is identified by its device certificate. No profile name or ID is sent.

Assumptions to confirm

  • Egress mode: I treated it as a vehicle mode the updater can read, reported by a vehicle signal. Please confirm what it is and which signal reports it. Other blocked modes can use the same rule.
  • Decided 2026-10-12: driving blocks both download and install. A download in progress pauses when driving starts, keeps its partial file and offset, and resumes after the gear has been in Park for 10 seconds. Downloads do not need the 1 AM window; installs do.
  • Manifest install rules can only add limits. The driving rule and battery minimum cannot be loosened by a manifest.
  • When space is short, an app that is already downloaded is installed first (if its rules allow) and its APK deleted. An APK that has not been installed is never deleted to make space, except when a newer version of the same app replaces it.
  • Vehicle state is the only gate for installs, apart from the manifest rules: driving is a strict no, parked is allowed. The service never asks apps what they are doing, so Navigation or music can stop when an update installs while parked. Tapping Update now counts as the user's consent, and the message appears when the install starts, with no countdown.
  • Apps restart when updated, so app teams should save their own state.
  • All numbers are placeholders: window 1 to 5 AM local time, auto needs WiFi of at least 2 Mbps, auto needs HV battery of at least 30% or charging, Update now needs at least 10% to download and 20% or charging to install, 12V minimum from the vehicle power team, free space of 2x the APK size, stall timeout 60 s, Park debounce 10 s.
  • Can the head unit wake at 1 AM (for example Garage Mode on Android Automotive)? If not, the automatic update runs in the first parked period after 1 AM instead.
  • Updates are per vehicle, not per profile. The service runs in the system user. Primary and secondary profiles can use Update now; guest is view-only.
  • Automatic downloads need a parked vehicle, WiFi, battery and storage. Automatic installs also need the 1 AM window, an idle vehicle (ignition off), and the app's install rules.
  • Decided 2026-10-12: cellular consent lives in Settings, not in the Update now flow. The "WiFi or cellular" option is shown only when the vehicle has a connectivity subscription; without one, downloads are WiFi only.
